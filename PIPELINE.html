Level 6 pipeline, as it runs now

How the best programs are produced in the last hour of the contest: a Rust beam search builds them, two CP-SAT polishers shorten them, and a harvest loop keeps the shortest valid program per item. Companion to STRATEGIES.html (the cycle players) and DOCS.html §7.11–7.12. The numbers are from the real runs; the animations are schematic.

1 · The Rust beam

ccc1 + ccc2

A state is the six emitters (offset, on/off), the matter on the zone cells (pattern + halo, as u64 bitsets) and the submissions done so far. Each tick, every kept state tries all 46 = 4096 commands (F/B/T/- per emitter, about 100M combos per second per thread). Each child is scored, and only the best W survive to the next tick.

score(child) 
  done  · BIG          submissions first
+ built               pattern cells that are M
− 1000 · bad_halo    stray M next to the pattern
+ mu · potential       emitters near chords rich
                      in unbuilt cells (beta, gamma)

Without the potential (mu = 0) the beam is about 2.5× worse. Each item gets several runs: big and default weights at each width, then random weight restarts with fresh seeds until its time budget (150–400 s) runs out. A program is kept only if it is strictly shorter than the best set and passes valid.

2 · The polishers

ccc1

The beam's programs are good but not tight. Two exact CP-SAT passes take a program and look for a shorter one that does the same job. After each submission the zone (pattern + halo) is all O, so a copy depends only on the emitter state it starts from, and pieces can be swapped independently.

3 · The harvest loop

every 5 min near the end

Every run writes full candidate files (one program per item) into ~/scratch/l6_*/out/. harvest6.sh pulls them from both boxes, merge6 keeps the shortest program per item that passes valid6 (the current best set is always a candidate, so it only ever improves), and the new best6 is pushed back. The runs take it as their base for the next pass.
